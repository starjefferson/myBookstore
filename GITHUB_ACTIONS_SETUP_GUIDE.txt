DIGITAL CONCIERGE BOOKSTORE
GITHUB ACTIONS REST API SCRAPE AND FIRESTORE SETUP GUIDE

================================================================================
WHAT THIS AUTOMATION DOES
================================================================================

This project has two separate, decoupled commands[cite: 1, 2]:

  node scripts/scrape.js

This queries the WooCommerce REST APIs for all three configured vendors (Masobe Books, 
Rovingheights, and Retala) and saves the collected catalog locally to[cite: 1, 2]:

  scraped_catalog.json
  lib/categoryFilters.json

  node scripts/seed.js

This reads scraped_catalog.json and performs quota-safe batch updates to upload 
those books to Firebase Firestore[cite: 1, 2].

GitHub Actions runs these commands automatically on a temporary cloud runner[cite: 1]:

  1. Download the repository code[cite: 1].
  2. Install Node.js 22 and project packages (npm ci)[cite: 1].
  3. Run scrape.js (fetches REST APIs; routes Rovingheights via ScraperAPI)[cite: 1].
  4. If scraping succeeds, run seed.js (batch upserts catalog and shipping zones)[cite: 1].
  5. Save a copy of the scraped JSON files as workflow artifacts[cite: 1].

The workflow is located at:

  .github/workflows/scrape-catalog.yml

All three vendors (Rovingheights, Retala, and Masobe) are fully enabled and active[cite: 1]. 
Rovingheights is routed through ScraperAPI's proxy pool to bypass Cloudflare WAF 
blocking on cloud runners[cite: 1].

================================================================================
IMPORTANT: LOCAL DEVELOPMENT STILL WORKS
================================================================================

Yes. You can continue running the commands locally on your development machine[cite: 1].

From the project folder, use:

  node --env-file=.env.local scripts/scrape.js

After checking the generated scraped_catalog.json, upload it manually with:

  node --env-file=.env.local scripts/seed.js

The npm equivalents are:

  npm run scrape
  npm run seed

However, because the standard npm scripts do not automatically load .env.local on 
older Node setups, use the explicit node --env-file=.env.local commands above unless 
your environment variables are already loaded another way[cite: 1].

The recommended local workflow is:

  1. Run scrape.js[cite: 1].
  2. Wait for "Catalog ingestion complete"[cite: 1].
  3. Inspect scraped_catalog.json for book count, vendor, and author values[cite: 1].
  4. Run seed.js only when you are ready to update Firestore[cite: 1].

The scraper does not write to Firestore[cite: 1, 2]. The seeder is the only command 
that writes the catalog to Firestore[cite: 1, 2].

================================================================================
PART 2: ADD GITHUB ACTIONS SECRETS
================================================================================

The workflow needs four repository secrets[cite: 1]. These are different from normal 
GitHub login credentials[cite: 1].

  FIREBASE_PROJECT_ID
  FIREBASE_CLIENT_EMAIL
  FIREBASE_PRIVATE_KEY
  SCRAPER_API_KEY

To add them:

  1. Open the GitHub repository in your browser[cite: 1].
  2. Click Settings[cite: 1].
  3. In the left menu, open Secrets and variables[cite: 1].
  4. Click Actions[cite: 1].
  5. Click New repository secret[cite: 1].
  6. Enter the exact secret name[cite: 1].
  7. Paste the matching value[cite: 1].
  8. Click Add secret[cite: 1].
  9. Repeat for all four values[cite: 1].

Use the values already in your local .env.local[cite: 1]:

  FIREBASE_PROJECT_ID=your-project-id
  FIREBASE_CLIENT_EMAIL=firebase-adminsdk-xxxxx@your-project-id.iam.gserviceaccount.com
  FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n..."
  SCRAPER_API_KEY=your_scraper_api_key_here

For FIREBASE_PRIVATE_KEY, paste the complete private key, including[cite: 1]:

  -----BEGIN PRIVATE KEY-----
  -----END PRIVATE KEY-----

Do not paste the variable name into the value field[cite: 1]. The value field should contain 
only the value[cite: 1]. GitHub masks secrets in normal logs, but do not print them yourself[cite: 1].

================================================================================
PART 3: CHECK THE WORKFLOW FILE
================================================================================

The repository contains[cite: 1]:

  .github/workflows/scrape-catalog.yml

Its important settings are[cite: 1]:

  schedule:
    - cron: "0 2 * * 1,4"

This means:

  - Runs twice a week: Mondays and Thursdays at 02:00 UTC (03:00 WAT)[cite: 1].
  - Uses Node.js 22 runtime for fast execution and dependency stability[cite: 1].
  - Passes SCRAPER_API_KEY to scrape.js so Rovingheights bypasses Cloudflare[cite: 1].
  - Runs pure Node REST API queries (no heavy Playwright binary downloads)[cite: 1].

GitHub Actions uses UTC, not your local Nigerian time[cite: 1]. Scheduled runs may start 
a few minutes after the exact cron minute depending on GitHub queue traffic[cite: 1].

It also includes workflow_dispatch, which provides a button for starting a run 
manually at any time[cite: 1].

Do this before waiting for the schedule:

  2. Open the repository on GitHub[cite: 1].
  3. Click the Actions tab[cite: 1].
  4. Select Catalog Scrape and Seed in the left column[cite: 1].
  5. Click Run workflow[cite: 1].
  6. Select the main branch[cite: 1].
  7. Click the green Run workflow button[cite: 1].

A successful run will show these stages[cite: 1]:

  - Check out repository
  - Set up Node.js
  - Install dependencies
  - Run REST Catalog Ingestion Engine
  - Seed Firestore
  - Upload catalog snapshot

The Seed Firestore step runs only if the scrape step succeeds[cite: 1]. This prevents 
an incomplete scrape from being uploaded[cite: 1].

================================================================================
WHAT HAPPENS IF THE ACTION FAILS
================================================================================

If scraping fails[cite: 1]:

  - The Seed Firestore step does not run[cite: 1].
  - Firestore is not altered by that workflow run[cite: 1].
  - Check if your SCRAPER_API_KEY secret is set correctly in GitHub[cite: 1].

If seeding fails[cite: 1]:

  - The scrape step completed successfully and uploaded the artifact[cite: 1].
  - Check if your daily Firebase quota was exhausted (Spark Plan limit: 20,000 writes/day)[cite: 1].
  - The seeder uses `{ merge: true }`, so re-running the workflow updates documents cleanly[cite: 1, 2].

================================================================================
FIRESTORE SAFETY AND QUOTA OPTIMIZATION
================================================================================

The seeder is designed specifically to preserve your free-tier Firebase quota[cite: 1]:

  1. Zero Read Operations: seed.js does NOT call `db.collection("books").get()`[cite: 1]. 
     This saves tens of thousands of read operations per sync[cite: 1].
  2. Chunked Batch Writes: Writes are split into chunks of 450 items per batch, well 
     below Firestore's 500-operation limit per batch request[cite: 1].
  3. Stable Document IDs: Each book uses a predictable ID (`vendor-page-slug`), so 
     repeating a seed updates existing entries rather than creating duplicate books[cite: 1].
